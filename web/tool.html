How scoring works

A multi-agent run is a set of threads passing messages. When it fails, the trace shows what happened but not where the handoff broke. The usual way to find out is to read the whole trace, or to have a model read it, which is expensive, changes its mind between runs, and cannot tell the person who has to fix the prompt which two lines to look at.

This tool runs fixed rules that explain themselves. Each rule compares events in the trace and, when it fires, names the events it compared. The same trace always gets the same score. No model is involved, and nothing you paste leaves your browser.

The score

Each of the five checks starts at 100 points. Every major finding costs 25 points and every minor finding costs 10. Only the first three findings from any one rule count against the score; the rest are still listed, tagged "same habit, not counted", because ten instances of one habit is one lesson rather than ten. A check never drops below 0.

The overall score is a weighted average of the five checks:

CheckWeightWhat it asks

85 and up: handed off cleanly. 60 to 84: the handoffs need attention before this run can be trusted. Below 60: a handoff broke. The same bands apply to each check as pass, needs work, or fail, and no run is handed off cleanly with any check below 60, whatever the average says.

Silent is not clean

A rule that cannot run on a trace says so instead of scoring 100. A single-thread trace has no handoffs to check; a trace without tool arguments cannot be checked for duplicate work; a trace without a roster cannot be checked for routing to an agent that lacks the tool. The report lists every silent rule with its reason.
